----Клиент-серверная архитектура
    Клиент-Бэкенд-Сервер(БД)
    HTTP - протокол передачи данных
    Стек Клиента:
        - web: JS
        - iOS: Swift
        - Android: Kotlin
    Стек Бэкенда:
        - c++
        - c#
        - python
        - java
        - scala
        - go
        - JS
    Стек БД:
        - Postgres
        - MySQL
        - Redis
        - MongoDB
    Клиент отправляет HTTP-запрос (ручка, метод, хэндлер, запрос, эндпоинт) на сторону Бэкенда
    Бэкенд отправляет SQL-запрос на сторону БД
    БД отправляет данные на сторону Бэкенда
    Бэкенд отправляет HTTP-ответ на сторону Клиента

----HTTP-запрос
    URL: (сама ссылка запроса, обязателен)
        https://meduza.io:443/api/w5/screens/news
        протокол - https (secured)
        Домен (хост) - meduza.io (до : или до /)
        Порт - 443 (по дефолту https - 443, http - 80) (от : до /)
        Путь - api/w5/screens/news (от / до ?)
        Квери - от ? до # в формате название=значение, разделяются &; может быть несколько; ограничение в 2048 знаков
        Якорь - от #; может быть только 1

    Headers: (свойства запроса и Клиента, обязателен)
        Host: https://meduza.io
        Accept: text/html
        type: Postgres
        Content-Type: application/json
        User-Agent: Mozilla/5.0 (Windows NT 6.1; WOW64)
        Accept-Language: RU, EN
        Accept-Charset: UTF-8
        Cookie: sessionid=FOCDNKIBFOJP

    Body: (информация о запросе, необязателен)
        [
            {},
            {},
            {},
            {}
        ]

----HTTP-ответ
    Status code: (статусы ответов)
    100-199 - информационные
    200-299 - успешные
    300-399 - перенаправления
    400-499 - ошибки Клиента
    500-599 - ошибка БД

    Headers: (свойства ответа и сервера)
    Content-Type: application/json
    Server: Microsoft-IIS/7.5
    Set-Cookie: sessionid=FOCDNKIBFOJP; expire=30d;
    Date: Sun, 04 Aug 2013 13:33:59 GMT
    Content-Length: 8434

    Body: (информация ответа)
    [
        {},
        {},
        {},
        {}
    ]

----Архитектурный стиль REST
    Возможные форматы в Body:
    - данные в формате JSON
    - данные в формате XML
    - Файл
    - HTML

    Типы запросов: 
    - GET (Получение данных) - идемпотентный - запрос для получения данных из БД - нет body
    - DELETE (Удаление данных) - идемпотентный - запрос для удаления данных из БД - есть body
    - POST (Отправка данных) - неидемпотентный - запрос для отправки данных в БД - есть body
    - PUT (Изменение данных) - идемпотентный - запрос для изменения данных в БД - есть body
    Редкие:
        - CONNECT - неидемпотентный - установка "туннеля" к серверу
        - OPTIONS - идемпотентный - параметры соединения
        - PATCH - идемпотентный - частичные изменения
        - TRACE - идемпотентный - тестовое сообщение
        - HEAD - идемпотентный - аналог GET
    
    Идемпотентность - свойство возвращать всегда один и тот же ответ

----JSON - формат данных
    JSON использует только 6 типов данных
    1. Строка - "текст"
    2. Число - 123
    3. Булеан - true/false
    4. null
    5. Массив - ["элемент 1", "элемент 2", "элемент 3"] - массив строк
    6. Объект - свойство, поле, ключ - всегда строка; значение - любое
    {
        "свойство": значение
    }

    Пример объекта:
    {
        "name": "iphone 13", (string)
        "price": 999, (number)
        "5g": true (boolean)
        "colors": ["white", "blue", "red"] (array)
    }

----XML - формат данных
    XML использует только теги, более защищённый формат, используется чаще в банках и других структурах требующих надёжности
    <тег>значение</тег>

    Пример тега XML:
    <bag>
        <laptop>macbook</laptop>
        <wallet>tinkoff</wallet>
        <id>passport</id>
    </bag>

    То же самое в JSON выглядит как:
    {
        "bag": {
            "laptop": "macbook",
            "card": "tinkoff",
            "id": "passport"
        }
    }

----Протоколы:
    HTTP-протокол:
        REST:
            Запросы:
                GET,
                POST,
                DELETE,
                PUT
            Body:
                JSON
                XML
                HTML
                Файл
        gRPC,
        graphQL - появляется звено между Клиентом и Бэкендом. 
        1. Клиент посылает всего 1 запрос в звено
        2. Звено распределяет его на несколько запросов в Бэкенд
        3. Бэкенд возвращает ответы на несколько запросов в звено
        4. Звено аккумулирует все ответы в один и отправляет в Клиент
        В итоге для Клиента есть условно один запрос и один ответ, который возвращает всё что нужно

    SOAP:
    Нет специального архиктектурного стиля
    Только один тип запросов
    В body только XML

----DevTools
    Вкладка Elements - работа с визуалом страницы, проверка шрифтов, цветов, картинок и т.д.
    Вкладка Console - показывает ошибки и предупреждения JS, можно вводить команды JS для тестирования
    Вкладка Sources - просмотр исходного кода фронта
    Вкладка Network - самая полезная для QA, просмотр всех запросов и ответов на запросы, статусы ответов, фильтры, throttling (имитация медленного интернета)
    Вкладка Performance - запись и анализ производительности
    Вкладка Memory - поиск утечек
    Вкладка Application - можно найти куки

----API - набор правил, протоколов и инструкций, который позволяет разным программам и сервисам общаться и обмениваться данными друг с другом
    Простыми словами API - контракт, который предоставляет программа "Ко мне можно обращаться так и так, я обязуюсь делать то и это"

----timestamp - использование формата времени в секундах прошедших в 1.01.1970 00:00:00

----Пагинация - распределение большого количества данных по страницам
    Пример: после отправки запроса на поиск телефона в Авито, он возвращает 100000 вариантов, но выдаёт только 50 вариантов на одной странице

----Postman - сервис для работы с HTTP-запросами и HTTP-ответами
    Использование коллекций
    Использование переменных {{}}
    Создание запроса:
        тип запроса
        параметры url (протокол, домен, порт, путь, квери, якорь)
        параметры header (в основном автоматически)
        параметры body
    Просмотр и работа с ответами
    Удобное создание автотестов через Snippets
    Интеграционное тестирование между запросами и ответами
